# Features

How Ligma behaves, in detail. For the short version, see the [README](../README.md).

## Tabs

- Tabs like the Figma desktop app, in place of the native title bar (on Windows the tab bar draws its own minimize, maximize and close buttons). Home (`https://www.figma.com/files`) is pinned on the left. Files opened from Home get their own tab, or focus the tab already showing them.
- Right-click a tab to pin or unpin it, copy its link, open it in the browser, reload it, move it to a new window, split the canvas with it, hide its file on Discord, or close it, the other tabs or all tabs. Pinned tabs sit after Home and show only their icon. Home's menu has Copy Link, Reload and Close Other Tabs.
- Drag a tab out of the bar to give it a window of its own, or onto another Ligma window's bar to move it there. The file carries on where it was, without reloading. Each window has its own tabs, and Home stays in the first window. A window closes with its last tab, and closing the first window closes them all. Next launch, `restoreTabs` reopens every window's tabs in the first one.
- Split view: right-click a file tab and choose Split View to share the canvas with the tab you're on, or drag a file tab over either half of a window's canvas (a blue outline marks it) and let go. Each file gets half of the canvas, side by side, or stacked when the canvas is no wider than 10:9, under one set of Figma's panels and one toolbar, those of the half you're working in, where they always are. Click in the other half to switch: the panels and toolbar become its own. The toolbar, image bar, menus and tooltips show in full over both halves. Drag the divider between the halves to share the canvas otherwise. Drag a selection from one half into the other and it moves to that file: it's copied over with Figma's own copy and paste, without touching the clipboard, follows the pointer until it's let go, back across too, and stays in the file whose half it's let go in, deleted from the other, which is undone with Undo there. Frames move by their name as well. Figma keeps each file's canvas between its panels, so both files' canvases span the whole space between the panels: rulers and scrollbars are those of the whole space, and the second half's file's leading ruler is under the first half. Selecting a tab outside the split, closing or moving one of its tabs, or End Split View in either tab's menu ends it (see `src-tauri/src/split.rs`). With `"uniformSplit": false` (Settings > Share panels and toolbar), each file takes its half of the window whole instead, with its own panels and toolbar, and nothing is dragged between them. `"splitView": false` (Settings > Split view) turns split view off and ends any split.
- A file whose name starts with an emoji shows that emoji as its tab icon.
- Point at a tab to preview it, like the Figma desktop app: a card under it shows how the tab last looked, its name and product, and whether it's asleep. Moving along the bar switches cards at once. Turn it off with `"tabPreviews": false` (Settings > Tabs > Preview tabs on hover). The image is taken when the tab was last on screen, so a tab restored from last time shows just its name until it's been opened.
- With `"restoreTabs": true` (Settings > Reopen tabs from last time), Ligma reopens your tabs, pins and the tab you had open. They're kept in `session.json` next to `settings.json`. Only the tab you had open loads; the others load when selected.
- Shortcuts: `Ctrl+T` (`Cmd+T` on macOS) new tab, `Ctrl+W` (`Cmd+W`) close tab, `Ctrl+Tab` / `Ctrl+Shift+Tab` switch tabs. While the settings window has focus, `Ctrl+W` (`Cmd+W`) closes it instead. Middle-click also closes a tab.
- Background tabs give memory back, and while a game is in front every tab sleeps (game mode, see [Memory](MEMORY.md)).
- A file comes back where you left it after its tab sleeps, is reloaded or is reopened from last time: the same page, position and zoom, and mode (Design, Draw, Motion or Dev Mode). Opening a file from Home does too, while a link to a layer still goes to that layer. Kept per file in the page's `localStorage` (see `src-tauri/src/view_state.rs`). Turn it off with `"keepFileView": false` (Settings > Remember where you were in files).

## Browsing

- Links inside `figma.com` stay in the app. All other web links open in the default browser.
- The Figma logo's menu in the editor leaves out Back to files (Home has its own tab) and Open in desktop app.
- Window size and position are saved between launches.
- Drag-and-drop goes to Figma, so you can drop images and files onto the canvas.
- On macOS, the app sends a Safari user agent so Figma treats the webview as a supported browser.

## Sign in with Google

Continue with Google signs in the way the Figma desktop app does, because Google doesn't allow sign-in inside embedded webviews: you approve Ligma on Figma's own page, signed in to Figma in a real browser, and Figma hands the sign-in back through a `figma://app_auth/redeem` link to the page you started from, which completes it. Figma only sends that link to `figma://`, whichever app asked (see `src-tauri/src/auth.rs`). Add account in Figma's account menu opens Figma's sign-in page in a new tab, and Continue with Google there works the same way, then switches that tab to the added account.

- **macOS:** the approval page opens in Apple's sign-in sheet, which shares Safari's cookies and catches the `figma://` link itself, so it works alongside the Figma desktop app (`web_auth.rs`).
- **Windows:** the page opens in your browser. Without the Figma desktop app, Ligma registers itself for `figma://` and also opens Figma's "Open in desktop app" links in a tab. With it, Ligma borrows `figma://` only while a sign-in waits (up to 15 minutes) and then puts Figma's entry back, also at the next launch if Ligma quit in between (`figma_scheme.rs`). A second Ligma started by a link passes it on and exits.
- A sign-in link is only accepted while a sign-in Ligma started is waiting, so a link from anywhere else can't sign you into another account.

## Local fonts

Figma loads installed fonts through its font helper, `FigmaAgent`. If the helper isn't running, Ligma starts it (from `~/Library/Application Support/Figma/FigmaAgent.app` on macOS, `%LOCALAPPDATA%/FigmaAgent/figma_agent.exe` on Windows) and stops it on quit. The helper is installed by the Figma desktop app or [Figma's font installer](https://www.figma.com/downloads/). On Windows, Figma also waits for the browser's Local Network Access permission, which WebView2 reports as "prompt" but never asks for, so Ligma reports it as granted to Figma tabs.

## Discord

- **Rich Presence** shows "Ligma" with the open file ("Editing …"), where you are in it and the selected tool. Under the file's name it shows the page's name in Figma Design and FigJam, the slide in Figma Slides and while presenting ("Slide 3 of 12", or "Frame 3 of 40" in a prototype), the chat's name in Figma Make, which asset you're on in Figma Buzz ("Asset 2 of 5") and the webpage's name in Figma Sites. The tool's icon (an art asset of the Discord application, see `scripts/discord-assets.mjs`) is the small image, named when hovered: blue while Ligma has focus, grey when you switch away. The large image is the app icon picked in Settings > App Icon, from `assets/discord-icons` (rendered by `npm run discord-icons`), or Ligma's logo.
- Settings can hide the file name (it then says "Editing a file", and where you are is hidden with it), the tool, or where you are for each product, or turn it off. In `settings.json` these are `"discordShowFile"`, `"discordShowTool"`, `"discordShowPage"`, `"discordShowFigjamPage"`, `"discordShowSlide"`, `"discordShowChat"`, `"discordShowAsset"`, `"discordShowWebpage"` and `"discordRichPresence"`.
- To keep one file private, right-click its tab and choose **Hide File on Discord**: while it's open Discord says "Editing a file", without its name or where you are in it, whatever the settings. **Show File on Discord** undoes it. With **Hide files by default** (`"discordHideFilesByDefault"`, under Show file name) it's the other way round: every file is hidden until you choose Show File on Discord for it. Both kinds of choice are kept by file key in `discord-hidden.json` in the app data folder, next to `session.json`, so they apply to every tab of that file, last across launches, and switching the setting keeps both.
- **Invites to files** (off by default, `"discordInvites"`) makes the open file a Discord party, sized by the people Figma shows in it. Friends can be invited from the + menu in a Discord chat, or ask to join from your profile, which Ligma asks you about. To leave join requests to Discord instead, turn off **Ask me about join requests** (on by default, `"discordJoinRequests"`). Joining opens the file in their Ligma, starting it if needed, and Figma shows it to them if they have access. It needs Rich Presence on for both of you.

## Settings

Settings (macOS: Ligma > Settings…, `Cmd+,`; Windows: the gear next to minimize) holds the options from `settings.json`, one page per category: Appearance (interface scale, color scheme and themes), App Icon, Features (toolbar modes, layer previews, image adjustments, copy as code, the classic home page and notifications), Tabs & Memory, Discord, Plugins and About. Changes are saved and apply right away.

`settings.json` is created on first launch in `%APPDATA%\dev.ligma.client` (Windows) or `~/Library/Application Support/dev.ligma.client` (macOS). After editing it by hand, restart Ligma.

## Appearance

- **Color scheme** (`"colorScheme"`: `"system"`, `"light"` or `"dark"`) sets light or dark for Figma and Ligma together and takes the place of Figma's own Theme setting, which Ligma keeps at System.
- **Themes** can be picked for each mode (`"lightTheme"`, `"darkTheme"`): Figma's own colors (`"figma"`), or Grove, Lagoon, Ocean, Midnight, Iris, Rose, Ember or Amber, which tint Figma's greys and give every editor's brand color (buttons, selection, menus; blue in Design, purple in FigJam and so on) the theme's color. The colors that stand for a product, like the Design and FigJam icons and buttons on Home, stay. In light mode, Figma's menus and tooltips are light too, in every theme (Figma draws them dark).
- Themes recolor Figma's panels, toolbars, menus, tooltips and buttons, and what Figma draws over the canvas (selection, rulers, labels), and with them the tab bar, the tab menu, prompts and the settings window, but not your designs: new shapes and frames get Figma's usual fills (see `dist/themes.js` and `src-tauri/src/appearance.rs`).
- **Interface scale** (`"interfaceScale"` in percent, 50 to 200) zooms Figma tabs, the tab bar, the tab menu, prompts and the settings window together, like a browser's zoom; − and + step through the usual zoom levels. The tab bar grows with it.
- The tab menu, prompts (update ready, join requests, errors) and the settings window are drawn by Ligma in Figma's style and follow the editor's light or dark theme. On Windows 11 they have no accent-colored border, just the system shadow.

## App icon

Settings > App Icon swaps Ligma's icon for one of up to 50 others in five collections: Colorways (Ligma Dark, on Windows only, as macOS turns Ligma's own icon dark with the system's icon style; Onyx, Ink, Slate, Pastel, Blush, Sunset, Tangerine, Citrus, Retro, Matcha, Forest, Tide, Cobalt, Ultraviolet, Prism, Mocha), Materials (Frosted, Chrome, Clay, Paper, Enamel, Gilded, Walnut, Marble), Graphic (Neon, Blueprint, Pixel, Riso, Terminal, Selected, Sticker, Bauhaus), Playful (Candy, Holo, Cosmos, Lava, Bricks, Balloon, Doodle, Knit, Buddies) and Seasonal (Fireworks, Sweetheart, Bloom, Pool, Harvest, Pumpkin, Festive, Snowfall). Each is drawn from the logo's own shapes (`dist/app-icons.js`). The picked icon is also the large image on your Discord status. After adding or redrawing an icon, run `npm run discord-icons` and commit `assets/discord-icons`. Discord loads the images from `main`.

- The picked icon (`"appIcon"`) is drawn into `app-icon.png` next to `settings.json` and put back on every launch (`src-tauri/src/app_icon.rs`).
- **macOS:** it shows in the Dock while Ligma runs and is set on Ligma.app as a custom icon, like Finder's Get Info does, so Finder, Launchpad and the Dock show it when Ligma is closed. An update replaces the app and its custom icon, and Ligma sets it again the next time it opens. If Ligma can't write to the app, only the Dock changes. The custom icon is flat: Liquid Glass's dark, tinted and clear styles only apply to Ligma's own icon.
- **Windows:** it shows on the taskbar, in Alt+Tab and on Ligma's Start menu, desktop and pinned taskbar shortcuts, which Windows 11's taskbar takes its icon from. An update puts the Start menu shortcut's icon back, so Ligma sets it again the next time it opens.
- Use Ligma's icon puts the original back and removes the custom icon from the app.

## Features

- **Toolbar modes** (`"showDrawMode"`, `"showDesignMode"`, `"showMotionMode"` and `"showDevMode"`, all on by default) choose which modes the switch on the right of Figma Design's toolbar offers, and the picker Figma's mode quick toggle shows. With one left, the toolbar shows no switch. Hiding the mode a file is in switches it to the first one shown, in the switch's order; if Figma puts you in a hidden mode itself, it still shows so you can switch back. Right-click the switch for a menu that turns each mode on or off, as in Settings. On accounts without Draw, where Figma shows a single Dev Mode toggle instead, the toggle hides when the mode it switches to is hidden. Figma's shortcuts and the Actions menu still switch to hidden modes. Changes apply right away, except that hiding the first mode reloads files already open, each once its tab is shown and its edits are saved (see `src-tauri/src/toolbar.rs`).
- **Lasso fill** (`"lassoFill"`, on by default) adds a tool to Figma Design's Creation tools menu, under Pencil, that fills what you draw around with color, as Procreate's lasso fill does. Hover and the arrow keys reach it like Pen and Pencil. It has Figma's Select area icon, and its cursor over the canvas, with the usual pointer over panels and the color picker, and as soon as another tool takes over. Picking it turns on Figma's Pencil, so the toolbar shows the lasso in the Pen button, and Escape, other tools and their shortcuts leave it as they leave Pencil. `P` or `Shift+P` pick Pen or Pencil again. While you draw, the area shows as Select area shows its own: a dashed outline in the selection color, tinted inside, closed back to the start. Escape cancels it, and Space-drag and other buttons still pan. When you let go, the loop is evened out to a point every pixel on screen and smoothed, which takes out the steps of whole-pixel mouse input and the shake of your hand, keeping turns over 120° as corners. It's then fitted with as few smooth cubic curves as stay within 2 pixels, so it comes out smoother than Pencil. It becomes a vector named "Lasso fill" with no stroke, in the innermost frame or section under where you started, leaving out auto layout as Pencil does, as one undo step. Like Pencil, it isn't selected after. The panel on the right sets its look while it's on, in Fill and Stroke sections like Figma's: each heading has its styles button and a + that adds a paint, and each paint its color, opacity, eye and −, so either section can have several paints or none. With none, the heading's styles button shows on hover, as in Figma. Under the strokes is their weight, with round joins. These are Pencil's own strokes and weight, sorted into the two sections by Ligma, so Figma keeps them as it keeps Pencil's, color picker and eyedropper included, and Pencil draws with them too. A color style takes the place of all of Pencil's paints, as it does for Pencil, so a style applied from a heading becomes that section's only paint and the other section is emptied; its − takes it away, Detach turns it back into that section's paints, and the other section's + detaches it first. Color variables work as paints in either section. Lassos drawn with a style or color variable from the file stay linked to it; ones from libraries, like Figma's iOS kits, come through as their color, as the page can't look those up by name. It works in files you can edit, where Figma offers its plugin API on the page. Changes apply right away (see `src-tauri/src/lasso.rs`).
- **Layer previews** (`"layerPreviews"`, off by default) show a small picture of each layer in the layers panel in every mode (Design, Motion and the rest), as Figma does only in Draw mode, with Draw mode's taller rows. Each mode keeps its own tools and right sidebar. Figma renders every preview, so large files may feel slower. Turning it off applies right away. Turning it on reloads files already open, each once its tab is shown and its edits are saved (see `src-tauri/src/layers.rs`).
- **Image adjustments** (`"adjustmentsClipboard"`, on by default) copy and paste the seven sliders of an image fill or stroke (Exposure, Contrast, Saturation, Temperature, Tint, Highlights and Shadows) without the image itself, which Figma's Copy/Paste Properties brings along. With the image picker open, `Cmd+Shift+C` (`Ctrl+Shift+C`) copies its adjustments, unless a text field has focus; Figma's Copy as PNG does nothing there. `Cmd+Shift+V` (`Ctrl+Shift+V`) pastes them, as one undo step, while they're the last thing copied or while an image's row in the Fill or Stroke section is highlighted; otherwise it's Figma's Paste over Selection. Paste and Reset change one image in each selected layer: the fill or stroke whose picker is open or row is highlighted or was clicked, or else the layer's top image fill. With an image selected, **Copy adjustments** and **Paste adjustments** also show after Crop in the bar above the toolbar (`"adjustmentsBar"`, on by default), Paste only once something is copied; they read and change the image whose row is highlighted in the Fill or Stroke section, or else each layer's top image fill. The button left of the picker's Rotate 90º, and right-clicking its sliders or an image's row, open a menu with Copy Adjustments, Paste Adjustments and Reset Adjustments; Copy reads the paint whose picker is open or row was clicked. Video fills have no sliders and are left out. What's copied carries to every tab. Files that can't be edited are left alone. See `src-tauri/src/adjustments.rs`.
- **AI actions in free projects** (`"hideFreeAiActions"`, on by default) hides Select area, Remove background, Edit with prompt and the More menu from the bar above the toolbar for a selected image, in files from a free (Starter) project. Crop and Ligma's adjustments buttons stay. A file counts as free by Figma's plan tier for the file the page loaded with, or else by the Free badge by its name (see `src-tauri/src/ai_actions.rs`).
- **Select object on this device** (`"localSelectObject"`, on by default, under AI actions in free projects, on Windows and Macs with Apple silicon on macOS 14 and later) puts Ligma's own Select object first in the image bar, in place of Figma's Select area, to pick out objects in one selected image as Photoshop's Object Selection does. The bar becomes Select object's own, like Figma's Select area: the tools, Select object, a brush and a lasso, the selection modes, New, Add and Take away, as Photoshop's, the brush's Size, Expand and Feather, then Isolate, Erase and Cancel. Fields take numbers, in the image's own pixels, or drag by their labels, and keys typed in them don't reach Figma. The bar's choices are kept while the tab is open. While Ligma reads the image, a blue shimmer runs over it. Then the object under the pointer is tinted and outlined as it moves, a click picks it, Shift-click adds another, Alt-click (Option-click) takes one away, and dragging a box picks the object in it. Add and Take away do what Shift and Alt do without them, and Shift and Alt still win. The brush, shown as a circle its size, paints in what was missed or, taking away, paints out what was overshot; `[` and `]` resize it. The lasso picks what's drawn around, as Photoshop's Lasso does, closing the shape when the button's let go: a new selection, or added or taken away as the modes say. The brush and lasso have a crosshair, with + or − when they add or take away. Picked objects show with marching ants, in the theme's selection color. `Cmd+Z` (`Ctrl+Z`) undoes the last change to the picks and `Cmd+Shift+Z` (`Ctrl+Shift+Z` or `Ctrl+Y`) redoes it, rather than undo in the file, while it's open. Isolate, or Enter, puts them in a new image layer right above, named after the layer with "[Isolated]", cropped to them and transparent around them, with a hard, antialiased edge, moved out by Expand, or in when it's negative, and softened either side by Feather, at their place and rotation, drawn as large as the image, up to 4,096 pixels across, as one undo step. The layer itself is left alone. Erase, or Delete, cuts them out of the image instead, with the same edge: the layer's fills, drawn as large, become one image fill with them transparent, and the fills before stay under it, hidden, as Remove background leaves them, as one undo step. Cancel, Escape, a click on the canvas off the image or selecting something else leaves. Space-drag, the wheel and other buttons still pan and zoom. Delete erases meanwhile, rather than delete the image (see `src-tauri/src/objects.rs`):
  - [SAM 2.1](https://github.com/facebookresearch/sam2) Tiny (Apache 2.0), Meta's Segment Anything, as ONNX, runs on the CPU with ONNX Runtime, as BiRefNet does. Its image encoder, quantized to 8 bits, reads the layer as Figma draws it, up to 1,024 pixels across, in about a second. Its mask decoder then finds the object at a point or in a box in tens of milliseconds, picking the best of the three it offers. The page asks for the outline under the pointer one request at a time, the latest point winning, and gets it back as SVG path commands, fitted as Vectorize fits its shapes, so it stays crisp at any zoom. Each mask is smoothed a cell either way, as the decoder's are checkered where it's unsure, and specks and pinholes smaller than a 4,000th of it are left out. Picks are combined in the decoder's logits, the largest for added ones and the smallest against taken-away ones, scaled up smoothly, and strokes of the brush and lassos are combined with them as how far inside each pixel is, a lasso filled row by row between where each crosses it. Isolate keeps what's inside, and Erase what's outside, with an antialiased edge half a pixel either side, found to a fraction of a pixel from the logits' slope, and Expand and Feather move and soften it by how far each pixel is from the edge, found with a Euclidean distance transform. The outline shows Expand too.
  - The model is 74 MB, so the first time Ligma asks before downloading it from Hugging Face, showing its progress in Figma's toast, and checks its SHA-256. It's kept in `models/sam2.1-tiny` in the app's local data folder. Settings > Features > Images > Object model downloads it ahead of time or removes it. Macs download ONNX Runtime with it, unless BiRefNet brought it already.
  - On Windows, Ligma lets Figma tabs start downloads one after another, which WebView2 otherwise holds back after the first without a click: each request is one (see `src-tauri/src/handoff.rs`).
- **Remove background on this device** (`"localRemoveBackground"`, on by default, under AI actions in free projects) puts Ligma's own Remove background in the image bar in place of Figma's. The top image fill of each selected layer is hidden and the cut-out added as a new fill above it, keeping its crop and adjustments, as one undo step. Showing the original fill again brings the background back. An image shown by several layers is cut out once. While it works, a white shimmer runs over each layer, as with Figma's own, and the X on Figma's toast cancels it, stopping the download or the model and leaving the layers as they were. Without a subject the image is left alone. The page hands the image to Ligma as a download and gets the PNG back (see `src-tauri/src/background.rs`).
  - **macOS 14 and later:** Apple's Vision finds the subject on your Mac, as Preview's Remove Background does.
  - **Windows:** [BiRefNet](https://github.com/ZhengPeng7/BiRefNet) (MIT), an ONNX model, runs on the CPU with ONNX Runtime, which is built into Ligma. It takes several seconds an image. The model is 224 MB, so the first time Ligma asks before downloading it from Hugging Face, showing its progress in Figma's toast, and checks its SHA-256. It's kept in `models` in the app's local data folder.
  - **Use BiRefNet instead of Vision** (`"useBackgroundModel"`, off by default, Macs with Apple silicon only) removes backgrounds with BiRefNet, as on Windows. ONNX Runtime (37 MB, Microsoft's build from GitHub) is downloaded and checked along with the model, as it needs macOS 14. The Mac app is ad-hoc signed, so `src-tauri/Entitlements.plist` lets it load a library it wasn't signed with.
  - **Background model** in Settings shows whether the model is downloaded, with its size, and can download it ahead of time, cancel the download, or remove it. Uninstalling Ligma removes it only with "Delete the application data" ticked.
- **Vectorize on this device** (`"localVectorize"`, on by default, under AI actions in free projects) puts Ligma's own Vectorize in the image bar, after Remove background, in place of the one in Figma's More menu. Each selected layer with an image is drawn as Figma shows it and traced into flat-colored vector shapes, stacked from the back, in a frame named after the layer with "[Vectorized]", right under it, at its position, size and rotation. The layer is hidden, as with Figma's own, and it all is one undo step. While it works, a blue shimmer runs over each layer, and the X on Figma's toast cancels it, putting back any layers already traced. It runs on your device on both platforms, with no download (see `src-tauri/src/vectorize.rs`):
  - **Regions:** the image is smoothed where it's alike, keeping edges, and split into regions of alike pixels, which are merged while they look alike in CIELAB, smallest and most alike first (Ward's method), so soft gradients become bands. Each region keeps its own average color, and regions within a few CIELAB units of a larger one share its color. Blends from antialiasing or soft edges go to whichever side they look most like, so edges fall halfway and logos keep their own few colors, without fringes. Edges are then moved to where the image changes between regions. Transparent areas are left out and see-through ones, like shadows, keep their opacity.
  - **Shapes:** each region is one filled outline, as with Figma's, drawn over the regions it lies in and reaching a little under those drawn over it, so no seams show. [visioncortex](https://github.com/visioncortex/visioncortex) (MIT or Apache 2.0), the library behind VTracer, finds the outlines, which are fitted much as Potrace does: corners are found first, the stretches between them straightened where only the steps of the pixels make them crooked, smoothed, and fitted with as few cubic curves as stay within 0.8 pixels. A small image drawn large is traced at its drawn size but smoothed by the size of its own pixels. An image that would give over 2,500 shapes is traced again, merging more.
  - **Recolor bar:** after vectorizing, a bar like Figma's takes the place of the image bar: Full color, Grayscale or Black and white, and Number of colors, from the traced colors down to one. Colors are merged as they look, in CIELAB, those most alike and covering least first, by Ward's method on how many pixels of each show, so a small accent that stands out stays until late. Merged colors take the color of the one that covers most. Each change is an undo step, and the traced colors come back in full at the top of the range. Done, Escape, or selecting something else closes it.
- **Copy as code without Dev Mode** (`"copyAsCode"`, on by default) adds **Tailwind**, **Tailwind (all layers)** and **React** to Figma's right-click menu under Copy/Paste as > Copy as code, after Figma's own CSS, CSS (all layers), iOS and Android, in every file you can edit on any plan, in place of the upsell for Dev Mode's Tailwind, React and more where Figma shows it. Tailwind copies the selected layers' classes, each under a comment with its name when there are several. Tailwind (all layers) copies them and every visible layer in them as nested HTML, text layers as `<p>` with their text. React copies a component for each selected layer, named after it, with the same markup as JSX and `className`. The classes are made from the CSS Dev Mode shows (the plugin API's `getCSSAsync`), using Tailwind's spacing scale and named sizes where they fit and arbitrary values otherwise. They're Figma's own menu items, so hover and the keyboard work as for the rest. It works in files you can edit, where Figma offers its plugin API on the page. Turning it off applies right away; turning it on applies to files opened after (see `src-tauri/src/copy_code.rs`).
- **Classic home** (`"classicHome"`, off by default) keeps Figma's long-standing home page on every account. Figma is trying a newer one on some accounts, where the top-left menu names a plan instead of you, the sidebar shows one plan's drafts and folders at a time, and lists filter by plan; with this on, those accounts get the usual layout, with you in the top left and your teams in the sidebar. Turning it off applies right away. Turning it on reloads the home page, once its tab is shown (see `src-tauri/src/home.rs`).
- **Figma notifications** (`"figmaNotifications"`, on by default) shows what lands in Figma's bell (comments, replies, mentions, invites and the rest) as desktop notifications: who it's from, what happened and where, and the comment. Clicking one opens its file or page in a tab, or the tab already showing that file. Figma's own web push needs a push service the system webviews don't have, so every 30 seconds a loaded Figma tab fetches the bell's feed for all your plans, and each unread entry Ligma hasn't seen shows. Entries already there at launch don't, a batch of comments that grows shows again, and more than three at once show as one. Nothing shows for the file you're looking at while Ligma is in front, as with Figma's own, and nothing is checked while every tab is asleep, as in game mode (see `src-tauri/src/notifications.rs`).

## People on pages

In a file others have open, each page in the left sidebar's pages list shows who's on it: their profile pictures, on the right of the page's row. More than three show as a count. Hovering a picture shows their name, and clicking it follows them to their page and view, as their picture in Figma's top right does. Other tabs of your own aren't shown, as in the top right. Ligma reads who's where from Figma's store and follows with Figma's own button, or the function behind it for people hidden in the top right's overflow (see `src-tauri/src/page_avatars.rs`).

## Plugins in the left sidebar

- Your plugins sit in the editor's left sidebar, under Figma's own buttons: development plugins, then every plugin and widget saved to your Figma account, each with its icon. Click a plugin to run it, or to pick from its commands if it has some; click a widget to put it on the canvas. Icons grow on hover.
- Right-click one there for its menu, like its … menu in Actions > Plugins & widgets: View details and Remove for saved plugins and widgets, Remove for development plugins.
- Settings > Plugins > Left sidebar shows or hides plugins (`"railPlugins"`) and widgets (`"railWidgets"`). With both off, they and their separator are gone.
- Hold Ctrl and drag a plugin to move it. The order is kept for every file; newly saved plugins come first.
- Settings > Plugins > Actions menu > Open on Plugins & widgets (`"actionsPluginsTab"`, off by default) opens Figma's Actions menu on that tab rather than All.

## Development plugins

Like the Figma desktop app's Plugins > Development > Import plugin from manifest…, which figma.com doesn't have.

- Settings > Plugins imports a plugin's `manifest.json` (built: `main` has to be JavaScript), switches it on or off, shows its folder or removes it. The list is `plugins.json` next to `settings.json`.
- Plugins that are on show in Figma's Actions panel under Plugins & widgets, as in the desktop app: marked Development, with their menu commands, Remove in their … menu, and a Development filter that lists only them with Import from manifest…. They show in the files whose editor they're made for (Design, FigJam, Slides or Buzz).
- Their files are read on every run, so a rebuilt plugin runs its new code.
- Ligma runs the code against the plugin API Figma's web editor offers on the page (`window.figma`, as in the developer console), so it needs a file you can edit. `figma.showUI`, messages with the UI, `figma.command`, the `run` and `close` events and `closePlugin` work as in the app. `figma.clientStorage` is kept per plugin in figma.com's IndexedDB.
- **Unlike the desktop app, plugins aren't sandboxed:** they run with the page's access, so import only ones you trust.
- Widgets, plugin parameters (quick actions) and the manifest's `build` command aren't supported (see `src-tauri/src/plugins.rs`).

## AI tools (MCP)

Figma's own MCP server goes through Figma's API, which a free plan can call 6 times a month (20 on Professional). [Figwright](https://github.com/awdr74100/figwright) gets around that with an MCP server on your computer and a plugin in each Figma file, which reads and edits the open file directly. Ligma takes the plugin's place, so there's nothing to import or run in Figma.

- Settings > Plugins > AI tools > Connect AI tools to your files (`"ligmaMcp"`, on by default) turns it on or off. It's called Ligma MCP in Figma's right panel. Before Figwright it was `"mcpBridge"`, off by default, which is no longer read, so it's on once for everyone after updating.
- Add Figwright's MCP server to your AI tool once. Quick connect lists the AI tools found on your computer (Claude Desktop, Codex, Cursor, Visual Studio Code, Windsurf, Gemini CLI and Antigravity), each with a switch that adds the server to its MCP settings or removes it. Ligma changes only its `figwright` entry and leaves the rest of the file as it was, and leaves alone a file it can't read. Claude Code gets a Copy Command button instead, as Claude Code writes its own settings all the time. A tool set up for another version of the server, or for Figma MCP Bridge, which earlier versions of Ligma used, shows Update, which puts `figwright` in place of the `figma-bridge` entry. Restart the tool afterwards.
- Set up by hand shows the JSON entry for any other tool's MCP settings, and the command that adds it to Claude Code for every project. The tool starts the server itself with `npx`, so it needs Node.js 20.19 or later. The server is pinned to the version of the plugin code Ligma includes, as their tools have to match. One that speaks another version of Figwright's protocol turns Ligma away, and Settings says so. See `src-tauri/src/mcp_clients.rs` for where each tool keeps its settings.
- Every file open in Figma Design, FigJam, Slides or Buzz connects on its own, by its name. An AI tool uses the file on screen unless it picks one (`list_files`, `use_file`), so two tools can work in two files. Settings shows how many are connected. A file in more than one tab is used from the one on screen.
- Figwright's tools read the document, selection, styles, variables, components, prototypes, motion and screenshots, and create and edit layers, components and variants, variables and styles, and export PDFs and videos (see its README). None of them run arbitrary code, which matters here: Figma's web editor has no plugin sandbox, so the plugin's code runs with figma.com's access to your account.
- Ligma runs Figwright's plugin code (`src-tauri/vendor/figwright/code.js`) in the tab, without its window, against the plugin API Figma's web editor offers on the page, like development plugins. So it only works in files you can edit, once they've loaded. Exported images come back as base64 rather than bytes.
- What AI tools do in a file shows in the MCP section of Figma's right panel, which Ligma takes over as Ligma MCP while this is on, so it's where people find it. Figma's own MCP status and setup are hidden meanwhile. Its chip says whether the file is connected (Connected, Working, Not connected, or Other version when the AI tool runs another version of the server), and its button opens Settings at AI tools. Under it are the file's latest three calls, newest first, with reads in grey and calls in a row to the same tool counted (×3). Show more lists them all in a box that scrolls past eight rows, and Show less goes back. Clicking the heading collapses the section, with the chevron Figma's sections show on hover, and Ligma remembers it. Clicking a call shows when it ran, how long it took, its arguments, and why it failed. The target button beside it selects and zooms to the layers it named or made. Figma only shows that section while nothing is selected, so otherwise Ligma's sits under the selected layers' heading. The last 50 calls are kept until the tab closes (see `PANEL_JS` in `src-tauri/src/mcp_bridge.rs`).
- A tab an AI tool used in the last 5 minutes isn't frozen or put to sleep. Asleep and frozen tabs aren't connected. Selecting one connects it again.
- The server listens on `127.0.0.1:3055`, and Ligma connects to it there, speaking Figwright's protocol (see `src-tauri/src/mcp_bridge.rs`).

## Updates

On launch and every hour Ligma checks the latest release and downloads a newer version in the background. Once it's ready, an Update now button shows in the tab bar (before Settings on Windows, after the traffic lights on macOS) to restart into it, or it installs when you quit. Only an update ready within a minute of launch, while Ligma is in front, also asks to restart in a prompt; later ones never take focus from what you're doing. The app is replaced in place, so you stay signed in. If an update can't be installed, Ligma says why and offers to download it or report it.

## Reporting problems

Use Report… in Settings (or Help > Report a Problem… on macOS). It opens a GitHub issue filled in with Ligma's version, the system and the end of `ligma.log`, for you to check and submit. The log is in `%LOCALAPPDATA%\dev.ligma.client\logs` on Windows and `~/Library/Logs/dev.ligma.client` on macOS.

## Security

Figma pages have no access to Tauri IPC. Only the local tab bar has permissions (`src-tauri/capabilities/tab-bar.json`).
